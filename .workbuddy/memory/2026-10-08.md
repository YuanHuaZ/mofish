### 关键决策（后续必须遵守）

- **引擎同名冲突**：五个游戏都叫 `engine.py`，因此一律用包内绝对导入
  `from <pkg> import engine as X`（如 `from klotski import engine as KE`），
  绝不用裸 `import engine`——否则同一进程里会串味。
- **数据文件定位**：用 `shared.common.find_game_data(name, folder)` / `load_game_json(name, folder)`，
  查找顺序 `_MEIPASS/<folder>/` → `_MEIPASS/` → 项目根/<folder>/。
  打包时用 `--add-data "<src>;<folder名>"` 打进包内同名子目录。
- **存档目录**：`data_dir()` = exe 同目录 / 项目根目录（非 frozen 时用 `ROOT` 而非 `HERE`），
  不可写则退回 AppData。
- **难度必须递增且可验证**：
  - 华容道 `minSteps` 50→116 严格递增（构建期 BFS 精确求解）。
  - 数字华容道难度分 = 初始曼哈顿距离 × 尺寸系数(3:1.00/4:1.08/5:1.16/6:1.24)，
    构建期在 420 个候选中挑最接近目标的一局并强制严格递增（10→191）。
- **后台线程**：AI / 求解器统一用 `common.WorkerKeeper` 持有引用，
  `closeEvent` 里 `keeper.stop_all()`；结果回调带世代号 `self.gen` 校验，丢弃过期结果。

## 追加：按游戏分包 + 难度提升（同日）

### 1. 目录改成「一个游戏一个文件夹」（对齐原 sudoku/ 的形态）

- 每个游戏目录自带：`<game>_app.py`（界面 + `launch()` + `--selftest`）、`engine.py`（纯逻辑）、
  关卡 `*.json`（sudoku/puzzles.json、klotski/levels.json、numberklotski/levels.json）、
  `启动<游戏>.bat`；klotski / numberklotski 另有 `build_levels.py` 生成题库。
- `shared/common.py`（公共）、`hall/launcher.py`（大厅）、根目录 `main.py`（入口）、`build_exe.py`（打包）。
- **同名 engine.py 的坑**：一律用 `from <pkg> import engine as X` 这种包内绝对导入，
  绝不用裸 `import engine`；各目录都加了 `__init__.py` 成为包。
- 数据定位：`shared.common.find_game_data(name, folder)` /
  `load_game_json(name, folder)`，顺序 `_MEIPASS/<folder>/` → `_MEIPASS/` → `项目根/<folder>/`。
  打包用 `--add-data "<src>;<folder>"`。
- `data_dir()` 改为：非 frozen 时返回 `ROOT`（项目根），不再用 `HERE`（shared/），
  保证源码运行的存档和 exe 同目录。

### 2. 华容道关卡 8 → 30

`klotski/build_levels.py`：保留 8 个经典布局，另外随机生成 4×5 布局（标准十子：
曹操 2×2 + 关羽 2×1 + 4 竖将 + 4 卒，恰 2 空格），用 `ProcessPoolExecutor` 并行 BFS 验证可解，
合并去重后按最优步数递增取样 30 关（最少步数 50 → 116），最优解一并写进 levels.json。

### 3. 数字华容道新增 + 难度严格递增

- 新增 `numberklotski/`（引擎 + 界面 + 15 关）。
- 难度分 = 初始曼哈顿距离 × 尺寸系数（3:1.00 / 4:1.08 / 5:1.16 / 6:1.24），
  档位：入门 <15 / 简单 <30 / 普通 <55 / 困难 <90 / 专家 <130 / 大师。
- `build_levels()` 每关采样 420 个候选，挑初始偏差最接近目标的一局，并**强制难度分 > 上一关**，
  实测 15 关难度分 10→191 严格递增（3×3→4×4→5×5→6×6）。
- 玩法：点相邻方块滑动、点同行/列整排滑动、归位方块变绿、方向键/WASD 推方块；
  3×3 用 BFS 给最优提示，4×4 以上用曼哈顿贪心提示；另有「自定义局面」（边长 3~6 + 打乱程度）。

### 4. 打包踩坑（重要）

- **`shutil.rmtree(workpath)` / `--clean` 会触发批量删除保护**，构建直接中断。
  对策：每次用带时间戳的全新 `build/work-<ts>` 与 `build/dist-<ts>`，不删任何东西；
  exe 用 `shutil.copy2` 覆盖到项目根目录。
- 打包后必须跑 `摸鱼游戏合集.exe --selftest` 验证题库确实进了包（看同目录 selftest.log）。

## 追加 3：象棋 / 五子棋支持局域网联机

### 新增 `shared/lan.py` + `shared/lan_dialog.py`

- **传输**：TCP 长连接 + 按行分隔的 JSON。消息：`hello / welcome / reject / move /
  undo_req / undo_ok / undo_no / rematch_req / rematch_ok / rematch_no / resign / ping / pong / bye`。
- **发现**：房主用 UDP 广播宣告房间（`magic=mofish-lan`，含昵称/端口/状态），
  **同时发给 `255.255.255.255` 和 `127.0.0.1`** —— 后者让同一台机开两个窗口也能互相发现。
  加入方绑 `DISCOVERY_UDP` 监听即可；房间 4 秒不广播就过期。
- **端口**：`DEFAULT_TCP = {gomoku:45680, xiangqi:45682}`，
  `DISCOVERY_UDP = {gomoku:45681, xiangqi:45683}`。
  默认端口被占时自动退到随机端口，靠广播里的端口号告知对方。
- **线程模型**：`_HostThread` / `_ClientThread` / `_DiscoverThread` 都是 QThread，
  收发在子线程、通过 Qt 信号回主线程；每个 `run()` 都套了兜底 try/except 发 `failed`，
  避免线程静默死掉。心跳 5s、空闲 26s 判超时。
- **坑**：`recv` 超时与对端关闭都返回空数据，必须用 `None`（超时）和 `b""`（关闭）区分，
  否则对端关闭后不会立刻感知。

### 悔棋的一致性规则（重要）

联机悔棋是「请求—同意」：发起方带上自己的颜色 `{"t":"undo_req","color":...}`，
两边跑**同一条确定性规则**：先撤 1 手；若撤完不是发起方行棋，就再撤 1 手。
这样「发起方重新可下」且双方步数完全一致（棋盘永远同步）。

### 游戏侧改动

- 两个游戏各加：头栏联机状态 chip、右侧「局域网联机」卡片（创建/加入 + 断开联机）、
  `open_lan / leave_lan / _close_net / _on_lan_message / _apply_undo / _lan_rematch`。
- 联机时 `self.net` 非空 → `_ai_turn()` 直接 return（没有 AI）、`_save()` 不落存档
  （避免联机局面污染人机进度）、难度/执子/模式下拉禁用、战绩不混进人机统计。
- 象棋 `do_move(mv, from_net=False)`：本地走子才发网络，收到对方的走子用 `from_net=True`
  （否则会回声无限循环）。
- 再来一局 = 双方各自交换先手，两边交换等价所以仍然一致。
- 五子棋新增「认输」按钮（联机用；人机模式认输记为一场负）。
